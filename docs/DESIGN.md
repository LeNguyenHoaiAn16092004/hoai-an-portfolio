# Design Specification

## 1. Visual direction

The visual language combines editorial design, restrained brutalism,
retro print/digital references, and technical interface details.

The result should feel handcrafted and slightly unconventional.

Reference inspiration may include the visual energy of JayGood, but do not
copy its layout, assets, typography, branding, or implementation.

## 2. Layout philosophy

Use controlled asymmetry.

Preferred techniques:

- Oversized typography
- Uneven columns
- Editorial whitespace
- Overlapping elements
- Large numbered sections
- Thin rules and dividers
- Small technical metadata
- Sticky elements where useful
- Horizontal compositions
- Variable section heights

Avoid:

- Uniform three-card grids
- Excessive rounded cards
- Dashboard-like panels
- Perfectly centered layouts everywhere
- Excessive shadows
- Generic hero sections

"Unconventional" must still be readable and navigable.

## 3. Typography

Use three complementary roles:

### Display

Large sans/grotesk type for headlines and section titles.

### Editorial

Serif type for selected narrative content.

### Technical

Monospace type for metadata, technologies, labels, dates, system-like
information, and small annotations.

Do not use too many font families. Prefer a controlled 2–3 family system.

Typography hierarchy should be obvious even without animation.

## 4. Light theme

Suggested starting palette:

- Background: warm off-white
- Primary text: near-black
- Secondary text: warm gray
- Border: dark neutral
- Accent: muted red / terracotta

Starting values are suggestions, not immutable requirements.

## 5. Dark theme

Suggested starting palette:

- Background: charcoal, not pure black
- Primary text: warm off-white
- Secondary text: muted gray
- Border: warm light neutral
- Accent: muted red / terracotta

Dark mode must feel intentionally art-directed rather than a simple color
inversion.

## 6. Navigation

Desktop:

- Small personal mark on one side
- Compact section navigation
- Theme control
- Optional local/system status

Mobile:

- Compact menu
- Full-screen or near-full-screen navigation overlay is acceptable
- Touch-friendly targets
- No hover-dependent behavior

## 7. Hero

The hero should communicate identity without using the generic phrase
"Hi, I'm X, a passionate developer."

Preferred ingredients:

- Large typographic statement
- Small technical metadata
- Personal identity
- A visual/3D artifact
- Scroll cue
- Optional status indicator

The hero should remain understandable if 3D is disabled.

## 8. Projects

Projects are the primary evidence of engineering ability.

Use an editorial list or mixed-size composition instead of a standard card grid.

Each project should expose:

- Number
- Title
- Short description
- Category
- Technologies
- Year
- Visual
- Case-study link

## 9. About

Keep the narrative concise.

Include:

- Short introduction
- Background
- Education
- Experience if applicable
- Current technical interests
- Skills
- Personal interests where useful

## 10. Lab

Lab is a space for experiments and unfinished ideas.

Examples:

- Architecture experiments
- API experiments
- UI experiments
- Animation experiments
- Data experiments
- Small prototypes

Clearly label experimental/unpolished work.

## 11. Notes

Notes communicate technical thinking.

Possible categories:

- Backend
- System Design
- Database
- Frontend
- Learning
- Engineering Lessons

## 12. Contact

End with a strong editorial CTA.

Provide:

- Email
- GitHub
- LinkedIn
- CV
- Optional contact form

Do not make a contact form mandatory for MVP.

## 13. Imagery

Prefer original project screenshots, diagrams, generated/created artwork, and
technical visuals.

Avoid generic stock photography.

## 14. 3D visual language

3D should look like an abstract digital artifact rather than a cliché robot,
floating laptop, or generic cube.

Potential directions:

- Abstract geometric sculpture
- Wireframe artifact
- Layered technical object
- Distorted editorial object
- Digital material study

Use a restrained palette matching the theme.

## 15. Responsive art direction

Do not simply scale the desktop layout.

The composition should be re-authored for each device class while preserving
the same content hierarchy.

## 16. Accessibility

Maintain:

- Strong text contrast
- Visible keyboard focus
- Semantic structure
- Logical heading order
- Reduced-motion support
- Touch target sizes
- Alternative text where appropriate
